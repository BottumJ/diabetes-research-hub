## Blocker (unchanged, now urgent) — git requires the user
git **cannot** commit or push from the sandbox. OneDrive denies `unlink`, so git can't manage `.git/index.lock` or temp objects: each git call leaves a stale 0-byte `index.lock` that blocks the next call. A commit attempt this run briefly corrupted the index ("bad signature"); recovered cleanly via `git read-tree HEAD` (**working tree intact, no data lost**). ~60 undeletable `index.lock.*` backups (~716K) have accumulated in `.git/` across many runs.

**Repo: 40 commits ahead of origin/main + 36 uncommitted working-tree files.**

**User fix (PowerShell, in the OneDrive working copy):**
```
del .git\index.lock
# optional cleanup of accumulated lock backups:
Get-ChildItem .git\index.* -Exclude index | Remove-Item -Force
git add -A
git commit -m "sync 2026-06-19 daily iteration"
git push
```
